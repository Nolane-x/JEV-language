## Honesty constraints

The release gate accepts `partial` and `unsupported` phenomenon coverage when those limits are published. It is designed to block silent semantic regressions, forced ambiguity resolution, missing-gold recall hidden behind conditional accuracy, unverified programs reported complete, UNKNOWN/TIMEOUT presented as proof, unexplained edit churn, incompatible extension partial loading, hidden generation, benchmark literals in runtime rules, and missing unsupported-case metadata.

`docs/unsupported-cases.json` is therefore part of release evidence, not a failure to be removed before release.

## Original M19/M20 remain separate

The original M19 gate requires blind human ratings, semantic accuracy, multi-turn coherence, template leakage, response diversity, latency/cost, and a failure taxonomy. Human ratings must not be fabricated.

The original M20 gate requires stable core package API documentation, ABI/schema versioning, conformance suites, migration policy, benchmark baseline, known limitations, replayable demos, and native-demo zero-generative audit.

After this release gate is verified, the next implementation work is to prepare M19 evaluation artifacts and then satisfy M20 package/release conformance.
